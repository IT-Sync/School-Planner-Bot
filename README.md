# School Planner Bot

Телеграм-бот, который помогает ученикам и родителям вести единое расписание уроков и внеурочных занятий. Приложение реализует сценарии: заполнение расписания по дням, вывод `/today` и `/week`, контроль пересечений и лимитов, запуск в Docker.

## Возможности MVP
- `/set_lessons` и `/set_extras` собирают расписание построчным вводом и полностью замещают выбранный день.
- `/today` показывает объединённый список уроков и кружков с учётом часового пояса пользователя.
- `/week` возвращает 7 блоков (Пн–Вс) и сортирует события по времени.
- Пересечения запрещены внутри одного типа (уроки с уроками, внеурочка с внеурочкой), есть лимиты 12/6 записей.
- Простое health API (порт `8088`) для мониторинга контейнера.
- `/share` создаёт ссылку-приглашение для импорта расписания (все события или только уроки) и она действует 1 день.

## Стек и архитектура
- **Python 3.11 + aiogram 3** — Telegram-слой и FSM.
- **PostgreSQL 15 + asyncpg** — хранение пользователей (`users`), уроков (`schedule`) и внеурочки (`extras`), миграции в `migrations/0001_init.sql`.
- **Сервисы** (`app/services`) инкапсулируют доменную логику и валидации, **репозитории** (`app/repositories`) работают поверх чистого SQL.
- **Парсеры** (`app/utils/parsing.py`) преобразуют пользовательский текст в DTO и проверяют формат `HH:MM-HH:MM`.
- Все компоненты запускаются через `docker-compose`; база и бот разделены на сервисы `db` и `bot`.

## Быстрый старт
1. **Зависимости**: Docker 24+, Docker Compose, git. Для локальной разработки без Docker понадобится Python 3.11 и PostgreSQL 15.
2. **Конфигурация**:
   ```bash
   cp .env.example .env
   # затем проставьте BOT_TOKEN и при необходимости переопределите порты/лимиты
   ```
3. **Запуск**:
   ```bash
   docker compose up --build
   ```
   - Postgres будет доступен на `localhost:5544`.
   - Health-check слушает `http://localhost:8088`.
   - При старте бот применяет миграцию `0001_init.sql` автоматически.

### Локальная разработка без Docker
1. Поднимите PostgreSQL c параметрами из `.env`.
2. Установите зависимости:
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install --upgrade pip
   pip install -e ".[dev]"
   ```
3. Запустите приложение:
   ```bash
   python -m app.main
   ```

## Команды и сценарии
| Команда        | Назначение |
| -------------- | ---------- |
| `/start`       | Создаёт пользователя, выводит список команд. |
| `/help`        | Показывает формат ввода и примеры. |
| `/set_lessons` | Выбор дня недели → ввод уроков → превью → сохранение. |
| `/set_extras`  | Аналогично для кружков/секций. |
| `/today`       | Возвращает события выбранного дня (уроки + внеурочка). |
| `/week`        | Показывает неделю целиком. |
| `/share`       | Создаёт ссылку для импорта расписания другим пользователем. |
| `/admin_stats` | (Только админ) Выводит статистику использования бота. |
| `/edit`        | Включает режим редактирования: выбрать день, запись, изменить название или удалить. |
| WebApp         | Кнопка «Открыть расписание» запускает мини-приложение с визуальным UI. |

**Формат ввода**: `HH:MM-HH:MM Название [локация] [учитель/комментарий]`. Дополнительные поля можно разделять пробелами, `|` или `;`. Примеры:
```
08:30-09:15 Математика 204 (Иванова)
16:00-17:00 Робототехника к.12
```

## Обмен расписанием
- `/share` показывает две опции: «Уроки + внеурочка» и «Только уроки». После выбора бот выдаёт deep-link вида `https://t.me/<bot>?start=share_<token>` и альтернативу `tg://resolve?domain=<bot>&start=share_<token>` для мгновенного открытия прямо в приложении.
- Отправьте ссылку приглашённому пользователю. При переходе и выполнении `/start` его расписание автоматически перезапишется данными владельца ссылки (в пределах выбранного типа событий).
- Ссылка действует сутки; после истечения срока нужно сгенерировать новую.
- Если у бота нет username, deep-link дублируется текстом `/start share_<token>` для ручного ввода.

| `ADMIN_IDS` | — | Список Telegram ID администраторов (через запятую), которым доступна `/admin_stats`. |
| `WEBAPP_URL` | — | Публичный HTTPS-URL мини-приложения (кнопка «Открыть расписание»). |

## Telegram WebApp

Мини-приложение разворачивается отдельным FastAPI-сервисом (порт `11002`). Оно повторно использует текущую БД и сервисы, проверяет `initData` Telegram и предоставляет REST API для фронтенда:

Кнопка `Открыть расписание` на главном меню бота содержит `web_app=WebAppInfo(url=WEBAPP_URL)` и запускает мини-приложение прямо в клиенте Telegram.

Для локальной отладки без Telegram можно задать `WEBAPP_DEV_USER_ID` — тогда запросы без заголовка `X-Telegram-Init-Data` авторизуются как указанный пользователь и логи FastAPI покажут, что используется dev fallback.



| Метод | URL | Описание |
| ----- | --- | -------- |
| `GET` | `/api/schedule/day?weekday=<1-7>` | Возвращает список занятий выбранного дня. |
| `GET` | `/api/schedule/week` | Возвращает расписание всей недели. |
| `POST` | `/api/schedule/day` | Создаёт занятие (урок/внеурочка) на выбранный день. |
| `PUT` | `/api/schedule/item/{id}` | Обновляет существующую запись (время, название, локация). |
| `DELETE` | `/api/schedule/item/{id}?type=lesson|extra` | Удаляет запись. |

Фронтенд расположен в `app/webapp/static` (адаптивный SPA на чистом JS). Для разработки можно обновить статику, а FastAPI автоматически её отдаёт. Telegram WebApp SDK подтягивается из клиента, `X-Telegram-Init-Data` добавляется во все запросы.

### Запуск мини-приложения

```bash
docker compose up webapp
```

Сервис доступен на `http://localhost:11002`. В боевом режиме следует проксировать его по HTTPS и передавать URL в `WebAppInfo`.

## Структура проекта
- `app/main.py` — точка входа, настройка aiogram, подключение к БД и запуск health-сервера.
- `app/services/schedule_service.py` — доменная логика расписания, объединение уроков и кружков, валидации.
- `app/repositories/*` — слой доступа к данным на `asyncpg`.
- `app/telegram/*` — хэндлеры, FSM-состояния и форматирование ответов.
- `migrations/0001_init.sql` — схема таблиц и индексов.
